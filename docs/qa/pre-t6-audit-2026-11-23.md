## F. Daftar GAGAL (berurutan dari paling berbahaya)

1. **[KRITIS] File `.env.local` di disk berisi rahasia nyata** (`SUPABASE_SERVICE_ROLE_KEY`, `DATABASE_URL`, `VERCEL_OIDC_TOKEN`). Risiko: kebocoran penuh DB/layanan jika mesin/log/backup bocor. Mitigasi: rotasi jika pernah terekspos; jangan commit; gunakan secret manager.
2. **[KRITIS] Signup publik aktif** (disable_signup=false). Risiko: spam akun palsu, beban DB/Auth. Mitigasi: nonaktifkan signup publik di dashboard atau aktifkan captcha/anti-bot; batasi domain email.
3. **[TINGGI] Fungsi publik EXECUTE terbuka ke `anon`** (semua 18). Risiko: permukaan serangan lebih besar; fungsi sensitif dapat dipanggil anon (meski dilindungi RLS). Mitigasi: `REVOKE EXECUTE ON FUNCTION ... FROM anon;` untuk fungsi non-publik.
4. **[TINGGI] Migrasi 000005-000008 tidak ada** (hanya 000001-000006). Risiko: audit baseline tidak lengkap; T6 mungkin membutuhkan migrasi yang hilang. Mitigasi: konfirmasi maksud tugas sebelum lanjut.
5. **[SEDANG] `dist/` berisi anon key JWT** (normal Vite, bukan service_role). Risiko: salah konfigurasi VITE_ bisa bocorkan service role; audit harus memastikan. Mitigasi: pastikan hanya anon key yang VITE_; jangan commit dist jika tidak perlu.
6. **[SEDANG] Role `wali` belum berfungsi** (policy RLS belum dibuat). Risiko: fitur wali (jika diaktifkan) akan gagal/leak. Mitigasi: implementasi policy wali sebelum fitur diaktifkan (T6?).
7. **[RENDAH] Tool scan (gitleaks/trufflehog) tidak terpasang**. Risiko: audit manual kurang komprehensif. Mitigasi: pasang gitleaks di pre-commit/CI.
8. **[RENDAH] Rabiul Awwal effective_days=3 (janggal)**. Risiko: data anomali; bukan keamanan. Mitigasi: keputusan Mudir.

### Usulan Perbaikan (tanpa menerapkan)

- Nonaktifkan signup publik atau tambah anti-bot.
- Cabut EXECUTE anon dari fungsi non-publik.
- Review matrix RLS vs SPEC bagian 8 sebelum T6.
- Buat kebijakan RLS `wali` jika fitur wali diaktifkan.
